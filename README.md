# Movie Recommender System

Учебный проект по курсу Программной инженерии: рекомендательная система для фильмов на датасете MovieLens 100k. Реализованы классические подходы RecSys, проведена оценка метрик, анализ проблем и ограничений.

## Выполнение задания

### Part I: Реализация RecSys подходов

Выполнено: реализованы 4 модели (3 классики + 1 эвристика).

| Тип | Модель | Описание |
|-----|--------|----------|
| Эвристика | Popularity | Топ фильмов по среднему рейтингу с фильтром по числу оценок (min_votes ≥ 50) |
| Классика | Content-based | TF-IDF на жанрах + косинусная похожесть |
| Классика | Item-based CF | Коллаборативная фильтрация по фильмам |
| Классика | User-based CF | Коллаборативная фильтрация по пользователям |

### Part II a: Проблемы реализации RecSys

Выполнено: документация в [docs/01_problems.md](docs/01_problems.md).

Разобраны 5 ключевых проблем:
1. Cold Start — новые пользователи, новые фильмы, новая система
2. Sparsity — разреженность данных (6.3% заполнения в MovieLens)
3. Popularity Bias — смещение в сторону популярного
4. Filter Bubble — замыкание пользователя в своём
5. Shilling Attacks — манипуляция рейтингами

Для каждой проблемы:
- описание сути;
- проявление в модели;
- возможные решения;
- недостатки решений;
- best practices из индустрии (Netflix, Spotify, YouTube, Amazon).

### Part II b: Проблемы в продакшене

Выполнено: документация в [docs/02_production.md](docs/02_production.md).

Разобраны 5 продакшен-проблем:
1. Latency — время отклика (требуется < 200 мс)
2. Scalability — масштабирование на миллионы пользователей
3. Data Drift — дрейф данных и изменение вкусов
4. Feedback Loop — петля обратной связи
5. Мониторинг и алертинг — как понять, что модель сломалась

### Part III: Оценка в продакшене

Выполнено: документация в [docs/03_metrics.md](docs/03_metrics.md).

Разобраны:
- ML-метрики (офлайн): Precision@K, Recall@K, NDCG@K, Coverage, Diversity, Novelty;
- бизнес-метрики (онлайн): CTR, Conversion Rate, Retention, Revenue;
- мониторинг: технические метрики, ML-метрики, бизнес-метрики, data quality;
- инструменты: Prometheus, Grafana, Evidently AI, WhyLabs;
- A/B-тестирование: методология и best practices.


## Рекомендательная система

Рекомендательная система отвечает на вопросы:
- какие фильмы похожи на этот (content-based, item-CF);
- что посмотреть именно мне (user-CF, content-based);
- что популярно прямо сейчас (popularity).

**Выбор сервиса:** фильмы (MovieLens 100k).

**Бизнес-контекст:** персонализация рекомендаций для стримингового сервиса
- Цель: увеличить вовлечённость пользователей, время просмотра, retention
- Ожидаемые результаты: +10–15% CTR, +5–10% retention, открытие long-tail контента
- Реальные результаты: Popularity-модель даёт лучший NDCG@10 (0.0708), но низкий coverage (1.17%)

## Быстрый старт

### Установка зависимостей

```bash
cd movie-recsys
pip install -r requirements.txt
```

### Запуск полного пайплайна

```bash
python scripts/run_all.py
```

Это выполнит:
1. Загрузку и обработку данных
2. Train/test split (80/20 по пользователям)
3. Инициализацию всех моделей
4. Оценку по метрикам (Precision@10, Recall@10, NDCG@10, Coverage)
5. Сохранение результатов в `reports/metrics.csv`

### Запуск отдельных моделей

```bash
python -m src.popularity
python -m src.content_based
python -m src.item_based_cf
python -m src.user_based_cf
```

## Реализованные модели

### 1. Popularity (baseline)

Подход: эвристический — топ фильмов по среднему рейтингу с фильтром по числу оценок (min_votes=50).

Преимущества:
- работает для любого пользователя, включая новых;
- очень быстрый (~1 сек);
- закрывает cold start.

Недостатки:
- не персонализировано;
- низкий coverage (~1% каталога);
- popularity bias.

Результаты: Precision@10 = 0.0706, NDCG@10 = 0.0708, Coverage = 0.0117.

### 2. Content-based

Подход: TF-IDF векторизация жанров + косинусная похожесть.

Преимущества:
- работает для новых фильмов (если есть жанры);
- высокий coverage (~26%);
- интерпретируемость.

Недостатки:
- плохо масштабируется;
- filter bubble (рекомендует только похожее);
- зависит от качества метаданных.

Результаты: Precision@10 = 0.0203, NDCG@10 = 0.0265, Coverage = 0.2614.

### 3. Item-based Collaborative Filtering

Подход: косинусная похожесть между фильмами по оценкам пользователей.

Преимущества:
- учитывает реальное поведение;
- стабилен — похожесть фильмов не нужно пересчитывать при добавлении пользователя;
- успешный подход Amazon.

Недостатки:
- cold start для новых фильмов;
- разреженность данных;
- популярные фильмы доминируют.

Результаты: Precision@10 = 0.0006, NDCG@10 = 0.0019, Coverage = 0.1389.

### 4. User-based Collaborative Filtering

Подход: косинусная похожесть между пользователями.

Преимущества:
- интуитивно понятно («люди с твоими вкусами любят вот это»);
- хорошо объясняется пользователю;
- максимальный coverage (~32%).

Недостатки:
- плохо масштабируется (матрица N×N пользователей);
- матрица пользователей меняется при регистрации нового;
- cold start для новых пользователей.

Результаты: Precision@10 = 0.0104, NDCG@10 = 0.0142, Coverage = 0.3171.


## Результаты оценки

Итоговая таблица (`reports/metrics.csv`):

| Модель | Precision@10 | Recall@10 | NDCG@10 | Coverage | Время |
|--------|--------------|-----------|---------|----------|-------|
| Popularity | 0.0706 | 0.0483 | 0.0708 | 0.0117 | 1.12 s |
| Content-based | 0.0203 | 0.0193 | 0.0265 | 0.2614 | 45.23 s |
| Item-CF | 0.0006 | 0.0014 | 0.0019 | 0.1389 | 1.79 s |
| User-CF | 0.0104 | 0.0136 | 0.0142 | 0.3171 | 2.29 s |

### Выводы

- Лучшая по NDCG@10 — Popularity: несмотря на простоту, эвристика работает лучше CF ИМЕННО на этом датасете
- Самая быстрая — Popularity: ~1 секунда против 45 секунд у content-based
- Максимальный Coverage — User-CF: 31.7% каталога против 1.17% у popularity
- Item-CF работает плохо, вероятно главная причина — высокая разреженность данных (6.3% заполнения)

### Рекомендации для бизнеса

1. Гибридный подход: Popularity для холодных пользователей + User-CF для активных
2. Exploration: принудительно добавлять разнообразие для борьбы с popularity bias
3. Matrix Factorization: попробовать SVD/ALS для работы с разреженностью
4. Мониторинг: внедрить онлайн-метрики (CTR, retention) для оценки реального эффекта
